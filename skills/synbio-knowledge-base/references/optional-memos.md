# 可选 MemOS 远程接入：开发检查

本版没有远程适配器，没有内置 API 地址、账号、知识库 ID 或密钥，也不会调用任何远程接口。此文是后续真实接入的检查要求，不是已经可执行的功能。

用户明确需要远程接入时，以当期官方文档和实际账号可用能力核验：

1. 明确服务产品、区域、API 版本、认证方法以及资料允许上传的范围。凭据通过环境变量或受管秘密存储提供，不写入 Skill、代码、日志、示例或 ZIP。
2. 为每个本地项目明确映射知识库／租户标识。查清上传、列表、处理状态、查询和删除是否都能限定到该范围；不能只在上传时隔离而查询全局。
3. 根据当期接口核对允许的文件类型、MIME、内容编码、大小和限流策略。某旧版本采用 data URI 的经验不能直接当成新接口要求；不复制旧包中的硬编码等待时间或 endpoint。
4. 验证“知识库文件检索”与“对话记忆检索”是否是不同能力。若返回的是 memory，不宣称能检索指定知识库文件；若无文件检索能力，明确降级为本地检索或暂停该功能实现。
5. 要求检索结果带原始文档 ID、版本、位置和可回查出处；用两个独立演示项目做添加、查询、更新和隔离测试。测试不使用真实团队机密。
6. 写入只重试可确认幂等或有明确去重方式的请求；区分已接收、处理中、成功、失败和超时。远程响应未知时先查状态，不能连续重复上传制造副本。
7. 正式接入前完成可审阅的适配器、配置示例和离线错误测试，再按用户授权范围执行外部操作。远程删除等额外动作按实际任务单独判断范围。

未通过这些检查时仍可使用本地功能。不要编造兼容性、已完成连接或检索效果，也不要把本指南当作当前服务能力的证明。
