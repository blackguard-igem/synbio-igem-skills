# 合成生物学执行蓝图

规划的目标不是把想法扩写成长文，而是让团队知道先验证什么、谁依赖谁、什么证据足以继续，以及何时应当改线。

## 选择蓝图类型

- 研究或 iGEM 项目：读取 [科研项目设计](references/research-project.md)，使用 [项目计划模板](assets/project-plan.md)。
- 课程：读取 [课程设计](references/course-design.md)，使用 [课程模板](assets/course-plan.md)。
- 科普活动：读取 [科普活动设计](references/outreach-event.md)，使用 [活动模板](assets/event-plan.md)。
- 用户在学习如何使用本 Skill：按需读取 [介绍](docs/介绍.md)、[操作指南](docs/操作指南.md) 或 [教学指南](docs/教学指南.md)。

## 三张图完成规划

为所选任务建立三个相互对应的视图；小任务可以合并展示，但不能丢掉其逻辑。

### 1. 成果图

写清目标受众、希望发生的变化、可观察成果和验收方法。把“做实验、办活动、制作课件”视为任务，不把它们本身当成效果。

### 2. 依赖图

逐项标出负责人角色、输入、资源、前置条件和交付物。预算、设备、合作、审批和人员尚未落实时标为依赖，不伪装成已有条件。

### 3. 证据闸门

为关键阶段写出：继续条件、暂停条件、需要复核的来源和备选路径。估算要保留假设与计算式；模拟数据、模拟访谈和示例成果必须标注为教学模拟。

## 规划规则

1. 先提取用户已经给出的时间、人员、能力、资源、受众和约束，再填补可逆的工作假设。
2. 将外部事实与团队决定分开。科学依据由原始论文或可靠机构材料支持；iGEM资格、费用、时间和安全要求按对应年份官方来源核验。
3. 任务粒度以可以交接和验收为准。每项任务至少能回答“谁、交什么、依赖什么、怎样算完成”。
4. 先安排一个能暴露主要未知项的小规模验证，再决定是否扩展。小规模验证的目的和通过条件必须预先写清。
5. 变更目标时同步检查依赖、预算、评价方式和风险登记，避免只修改标题或摘要。
6. 生物相关计划只提供与任务相称的概念与管理层设计。危险生物体、危害增强或检测规避内容不转换成可执行优化步骤。

## 输出与协作

交付一份能直接开工的蓝图：范围、三张图、近期任务、未决事项和复盘节点。用户要简版时压缩呈现，不机械填满模板。

其他 Skill 都是可选协作者：`synbio-expert` 提供证据卡；`igem-mentor` 提供当年赛事证据；`synbio-knowledge-base` 保存可追溯材料；`synbio-video` 和 `synbio-cue-cards` 处理明确要求的传播交付。缺失时保留接口字段并继续完成当前蓝图，不宣称调用成功。

交给 OpenMAIC 等课堂平台时，输出“受众—学习成果—章节—互动—测验—来源—禁止外推项”的课程简报；平台生成页面后仍需内容复核。维护与参考范围见 [来源说明](references/source-notes.md)。
