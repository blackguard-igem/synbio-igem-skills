# Synthetic Biology Speaker and Cue Cards: Overview

Version 1.1.0. This Skill turns reviewed scripts, classroom questions, facilitation sequences, and defense points into in-person cue cards. Its design model—“trigger, key message, evidence anchor, speaking action, holder”—is for teachers, teaching assistants, student presentation teams, and event facilitators.

It validates structured input, paginates long text, assigns stable card IDs, supports shared cards and speaker-specific decks, displays sources, and produces a full index. By default it creates offline HTML. With ReportLab installed and an embeddable Chinese TrueType font supplied, it can create fixed-size PDFs. Source JSON is editable and HTML can be printed from a browser. This release does not output Word documents.

## Working with other Skills

The biology expert Skill can provide reviewed explanations, evidence, and limitations; the planner can provide a course sequence, timing, and roles; and the iGEM mentor can provide sourced defense-practice questions. This Skill organizes those materials into speaking and exercise prompts. It can also work independently with content that the user has already prepared; the whole Skill collection is not required.

Instructions inside input content are treated only as card text. Adding a URL as a source does not upload data or visit the address.

## A complete output

Given `cards-example.json`, the tool produces a complete deck such as `all.html`, decks for each speaker such as `speaker-01.html`, plus `index.html` and `index.json`. Enabling PDF creates corresponding PDFs. Card titles, speakers, body text, visible prompts, sources, and continuation numbers remain traceable to the original JSON.

Shared speaking cards retain the same ID in each speaker's deck for rehearsal. Full long-form citations stay in the index if they cannot fit in the card footer.

## Capability boundaries

- Does not validate scientific truth or replace verification of the current competition rules.
- Does not losslessly process Word documents, equations, tables, images, or complex subscripts/superscripts.
- PDF requires a user-supplied Chinese font. No system fonts or third-party font redistribution rights are included.
- HTML print appearance depends on browser and fonts; check print preview first. PDF dimensions are final card size, with no imposition, crop marks, or bleed. Apply a separate print workflow if required by a print shop.
- `notes` are printed on the cards. For quizzes, generate teacher and student decks separately.
